# Angel Wings - Backend + Admin

## Стек

- **Backend**: Node.js + Express + Prisma ORM
- **Database**: SQLite (Prisma)
- **Frontend Admin**: Vue 3 + Vite + Pinia
- **Auth**: JWT

## Запуск

### 1. База данных

SQLite-база задаётся через `DATABASE_URL` в `server/.env`.

### 2. Backend

```bash
cd server

# Установка зависимостей
npm install

# Настройка .env
cp .env.example .env
# Отредактируй .env, в том числе DATABASE_URL для SQLite

# Генерация Prisma клиента и миграция
npx prisma generate
npx prisma db push

# Заполнение БД тестовыми данными
npm run db:seed

# Запуск dev сервера
npm run dev
```

### 3. Admin Panel

```bash
cd admin

# Установка зависимостей
npm install

# Запуск dev сервера
npm run dev
```

## Доступы

После `npm run db:seed`:

- **Admin**: `admin@peptidi.shop` / `admin123`
- **Админка**: `http://localhost:5173/admin`

## API Endpoints

### Auth
- `POST /api/auth/register` - Регистрация
- `POST /api/auth/login` - Вход
- `GET /api/auth/me` - Текущий пользователь

### Products (public)
- `GET /api/products` - Список товаров
- `GET /api/products/:slug` - Один товар
- `GET /api/products/:id/recommendations` - Рекомендации под товаром
- `POST /api/products/cart-recommendations` - Рекомендации по составу корзины (`productIds`)

### Products (admin)
- `POST /api/products` - Создать
- `PUT /api/products/:id` - Обновить
- `DELETE /api/products/:id` - Удалить

### Рекомендации товаров на существующей SQLite-базе

Перед обновлением сервера сделайте резервную копию базы. Затем из каталога `server` выполните:

```bash
npm run db:generate
npm run db:recommendations
```

Вторая команда создаёт таблицу рекомендаций и один раз заполняет подборки для 20 товаров из каталога. Её можно запускать повторно: отредактированные администратором подборки не перезаписываются. Настройка находится в форме редактирования товара, отдельно для страницы товара и корзины.

### Избранные ПВЗ на существующей SQLite-базе

Перед обновлением сервера сделайте резервную копию базы. Затем из каталога `server` выполните:

```bash
npm run db:favorite-pickups
npm run db:generate
```

Команда идемпотентно создаёт таблицу избранных ПВЗ. API также создаст её при первом обращении, но предварительное выполнение команды позволяет проверить схему до публикации. Гостевые избранные хранятся в браузере и при входе переносятся в аккаунт, если в нём есть свободные места (не более 10 ПВЗ).

### Карта ПВЗ в корзине

Для интерактивной Яндекс Карты получите ключ сервиса **JavaScript API** в кабинете разработчика Яндекса и ограничьте его доменами публичного сайта. Перед сборкой `vue-app` задайте `VITE_YANDEX_MAPS_API_KEY` в `vue-app/.env.production` (образец — `vue-app/.env.example`) либо в окружении команды `npm run build`. Ключ `YANDEX_GEOCODER_API_KEY` из `server/.env` предназначен для другого API и для карты не подходит. После изменения ключа пересоберите и опубликуйте `vue-app`; без ключа список ПВЗ остаётся доступен, но карта не загружается.

### Блог

Публичные страницы: `/blog` и `/blog/:slug`. Редактирование: раздел «Блог» в существующей админке. Новые записи создаются черновиками; только опубликованные статьи попадают в публичный API и карту сайта. Семь демонстрационных материалов можно добавить **только как черновики** для последующей редакторской проверки.

Роль «Копирайтер» назначается администратором в разделе «Пользователи». Она даёт вход в админку и полный доступ только к разделу «Блог» (статьи, категории и изображения); остальные административные API требуют роль `ADMIN`. Для нового сотрудника создаётся временный пароль и отправляется приглашение на email. Схему БД для этой роли менять не нужно: поле роли уже строковое. После обновления сервера пересоберите админку.

Перед развёртыванием сделайте резервную копию SQLite-базы. Из каталога `server` выполните:

```bash
npm ci
npm run db:generate
npm run db:blog
npm run db:blog-drafts # необязательно; добавляет примеры как черновики, не меняет существующие
```

Локальная проверка (на временной копии базы): `node --test src/routes/blog.test.js`.

### Роли админ-панели

Перед выкладкой новой версии API создайте резервную копию SQLite-базы. Затем в `server` выполните `npm ci`, `npm run db:generate`, `npm run db:roles` и перезапустите API; после этого соберите и выложите `admin`. `db:roles` только добавляет таблицу ролей и не изменяет существующих пользователей. Администратор создаёт роли в разделе «Роли» и назначает их в разделе «Пользователи». Встроенные «Администратор» и «Копирайтер» остаются без изменений; управление пользователями и ролями не делегируется. Проверка прав выполняется на сервере при каждом запросе, в том числе для уже активных сессий.

Локальная проверка: `node --test src/routes/adminRoles.test.js` (временная база, без изменения рабочей).

Затем соберите `vue-app` и `admin` обычным способом и перезапустите API. Для выдачи поисковикам готового HTML статьи и динамической `/sitemap.xml` добавьте маршруты из [nginx-blog.conf.example](deploy/nginx-blog.conf.example) в **публичный** server block Nginx до SPA fallback; проверьте API-порт и выполните `nginx -t` перед перезагрузкой. Без этого шага Vue-страницы работают, но прямой HTML-ответ не содержит серверных SEO-метатегов. Путь к собранному сайту по умолчанию определяется относительно `server/src/routes/blog.js` как `vue-app/dist`; при другом размещении задайте `SITE_DIST_DIR`.

Для подписки необходима настроенная почта (SMTP или email relay): посетитель получает письмо с подтверждением, и до подтверждения адрес не попадает в аудиторию «Подписчики блога» существующего раздела «Рассылки». Ссылка отписки добавляется к письмам этой аудитории. Перед включением подписки на рабочем сайте проверьте, что её описание внесено в действующую политику обработки персональных данных.

### Categories
- `GET /api/categories` - Список
- `POST /api/categories` - Создать (admin)
- `PUT /api/categories/:id` - Обновить (admin)
- `DELETE /api/categories/:id` - Удалить (admin)

### Orders
- `POST /api/orders` - Создать заказ
- `GET /api/orders/my` - Мои заказы (auth)
- `GET /api/orders/:id` - Детали заказа (auth)
- `PUT /api/orders/:id/status` - Статус (admin)

### Admin
- `GET /api/admin/stats` - Статистика
- `GET /api/admin/users` - Пользователи
- `POST /api/admin/users` - Создать пользователя
- `GET /api/admin/products` - Все товары
- `GET /api/admin/orders` - Все заказы
